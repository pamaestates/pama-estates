# Polish property editorial approval — repository-only, preview-safe

The Polish property catalogue and detail pages share one privacy-sanitized public feed with EN. Approved Polish **marketing** copy is separate from the public property facts.

The source-controlled file `src/content/pl-approved-properties.json` starts EMPTY. No content is authorized for automatic publication. Its record schema is `{reference, englishFingerprint, title, description, status:"APPROVED", approvedAt}`. A valid record must refer to the exact current public property `listingReference` and match the fingerprint generated by `sourceFingerprint(property)`. The record needs a valid approval timestamp. Conflicting records and changed EN source fail closed to the existing Polish placeholder.

To add records, obtain founder/editorial approval of EACH Polish description, review accuracy against source facts, log the approval separately, and request separate WRITE approval for the exact Git change. Do not expose owner contact, exact acquisition cost, credentials, or PAMA Core private data. A Git repository content approval is not permission to publish to production.

No admin API, database migrations, operational writes, paid translation or runtime management are implemented. This avoids new infrastructure and data-integrity risks. Before production, test with at least one non-sensitive approved fixture, verify stale-source invalidation, run EN/PL browser QA, and obtain publication authorization. Polish SEO remains noindex independently of this gate.
